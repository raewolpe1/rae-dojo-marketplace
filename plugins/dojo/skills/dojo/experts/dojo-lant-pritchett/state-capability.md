# State Capability

## When to Use
- When debating why reforms or policies fail to produce expected outcomes.
- When evaluating whether the state can deliver the demands being placed on it.
- When designing reform sequences that depend on implementation capability.

## Fails When
- **The capability is so absent that the conversation is about basic state functions** — different framing needed.

## Core Concept

State capability is the central variable distinguishing developed from developing countries — not policy quality. Many developing countries have good policies on paper. The implementation capability that makes policies real is what is largely absent.

Capability has multiple dimensions: technical capability (knowing what to do); administrative capability (organisational machinery for doing it); political capability (sustaining the work against contestation); and what Pritchett, Andrews, and Woolcock call "intrinsic capability" — the embedded organisational routines that produce results reliably.

The empirical observation that underpins the framework: developed and developing countries adopt similar policies; the developed ones implement; the developing ones do not. The discourse has historically attended to policy quality; the implementation gap is the binding constraint.

Capability is built through doing, not through training, planning, or technical assistance. Organisations that solve problems build capability; organisations that adopt forms without function (isomorphic mimicry) do not. PDIA operationalises capability-building through iterative problem-solving.

For South Africa: state capability has been a substantial concern across the post-1994 period, especially after the decade of state capture eroded specific institutional capabilities. The rebuild requires both removing the captured patterns and building the underlying capability — a long-horizon project.

## How to Apply

1. **Diagnose capability honestly** — not in general but in specific organisational functions.
2. **Match policy demands to capability** — don't demand sophisticated implementation from organisations without basic capability.
3. **Build capability through doing** — PDIA approach.
4. **Sequence sophisticated functions** behind basic ones.

## Examples

**Situation:** Eskom's operational and financial collapse.

**Application:** The collapse is a state-capability story across multiple dimensions: technical capability (engineering and operations); administrative capability (procurement, financial management); political capability (insulation from interference); intrinsic organisational routines. Rebuilding requires all four; piecemeal interventions on one or two do not produce sustainable capability.

**Result:** A diagnosis that engages with what actually needs to change.

## Anti-Patterns

**Don't:** Treat capability as something that can be "built" through training programmes.
**Why:** It is built through organisational doing. Training is necessary, far from sufficient.

**Don't:** Imagine sophisticated reform fixes capability problems.
**Why:** Reform demands capability; it doesn't supply it.

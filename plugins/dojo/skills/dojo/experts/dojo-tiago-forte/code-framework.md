## When to Use

Use the CODE framework as a diagnostic for any knowledge-work bottleneck. If you feel overwhelmed by information, you have a Capture problem. If you cannot find what you need when you need it, you have an Organise problem. If your notes feel dense and hard to use, you have a Distil problem. If you have abundant knowledge but struggle to produce finished work, you have an Express problem. CODE maps the full lifecycle of knowledge from intake to output.

## Fails When

CODE fails as a strict linear sequence. In practice, the four phases overlap and loop — you often Capture while Expressing, Distil while Organising. Treating CODE as a rigid pipeline creates bottlenecks rather than flow. The framework is a diagnostic and orientation tool, not a production assembly line.

## Core Concept

CODE is Tiago Forte's framework for the lifecycle of a piece of knowledge. It stands for:

**C — Capture**: saving ideas, insights, quotes, observations, and resources that resonate. The emphasis is on resonance rather than relevance — you capture what strikes you as interesting, useful, or beautiful, trusting that future projects will reveal why. The enemy of capture is over-filtering: people discard things because they cannot immediately see the use, then forget them entirely. A permissive capture habit is the foundation of a working Second Brain.

**O — Organise**: placing captured material where it will be most useful when needed. Forte insists organisation should serve retrieval, not taxonomy. The primary organising principle is PARA: which project does this serve? Which area does it support? If neither, is it a useful resource? Organisation is deliberately fast and imperfect — the goal is "good enough to find later," not archive perfection.

**D — Distil**: extracting the most essential content from what you have captured. Progressive Summarization is the primary Distil technique: bold the most important passages, highlight the single most essential idea, and optionally write a brief executive summary. Distillation happens over time and through use, not in one upfront session. The question to ask: "What is the most important insight here for someone in a hurry?"

**E — Express**: using your knowledge to create something. Expression is the purpose of the entire system — without it, capture and organisation are elaborate procrastination. Forte emphasises that expression does not always mean a finished product; intermediate packets (discrete, reusable chunks of work — outlines, frameworks, templates, rough drafts) count as expression. Each act of expression tests and refines the system: you discover what is missing from your Second Brain by trying to use it.

The most important move CODE makes is to **separate consumption from creation**. Most knowledge workers blur these two activities. CODE names them separately so they can be scheduled, optimised, and evaluated on their own terms. You should not evaluate an article while reading it (Capture mode), nor should you try to write while simultaneously collecting more material (Express mode). The modes require different cognitive states.

CODE also inverts the typical relationship between knowledge and work. Most people think: "I need to know more before I can produce anything." CODE says: "I produce by assembling what I already know, and production reveals what I need to learn." This shifts the locus of control from information to projects. You do not read until you know enough; you start a project and let the project pull the knowledge you need.

The CODE cycle is generative: each round of expression produces artefacts (intermediate packets, finished pieces, refined notes) that feed back into future capture cycles. A Second Brain built with CODE does not just store information — it compounds over time as each project enriches the raw material available to future projects.

## How to Apply

1. **Audit your current bottleneck first**: which phase of CODE is weakest? If you have hundreds of saved articles you never revisit, the bottleneck is Distil, not Capture. If you produce nothing despite a large knowledge base, the bottleneck is Express.
2. **Set up a capture inbox**: a single, trusted location where all incoming material lands before organisation. This prevents the friction of deciding immediately where something goes.
3. **Schedule brief Organise passes**: do not let the inbox overflow. Spend five minutes daily or thirty minutes weekly moving captured items into PARA categories.
4. **Distil on re-encounter, not upfront**: when you revisit a note during a project, spend sixty seconds bolding the key passages. Do not schedule "summarization sessions" — let use drive depth.
5. **Start Expressing earlier than feels comfortable**: the most common CODE failure mode is waiting until you know enough to express. Set a project deadline that forces expression from whatever you have. Intermediate packets count.
6. **Review what the expression revealed**: after publishing, presenting, or submitting something, note what was missing from your Second Brain and add a capture task for that gap. CODE improves through iteration.

## Examples

**Example 1: A consultant building a workshop**
A consultant runs workshops on change management. Using CODE: she Captures articles, research summaries, client anecdotes, and framework diagrams over two years (resonance filter: anything that might explain why change fails). She Organises these under PARA — some under the active "Q3 Workshop" project, most under a Resources folder called "Change Management". When the workshop deadline approaches, she Distils by Progressive Summarization — bolding key stats, highlighting a single striking finding from each source. She Expresses by assembling an outline from her intermediate packets (a framework slide deck from a previous engagement, a case study template, three distilled research notes). The workshop slides come together in four hours rather than four days.

**Example 2: A writer struggling to finish articles**
A blogger writes about urban planning but consistently abandons drafts after 400 words. Analysis via CODE: his Capture habits are strong (he reads voraciously and saves everything). His Organise habits are weak (everything lands in a flat "Writing" folder). His Distil habits are non-existent (none of his saved notes have been summarized). His Express mode activates only when he sits down to write — too late. He implements PARA for organisation, begins bolding saved passages during reading, and starts treating 400-word fragments as intermediate packets rather than failed drafts. Within a month he has assembled three complete articles from previously abandoned fragments.

## Anti-Patterns

1. **Treating CODE as strictly sequential**: many people interpret CODE as a pipeline — first capture everything, then organise, then distil, then express. In reality the phases interweave. You Distil while Organising (adding a quick bold before filing), and you Capture while Expressing (saving a reference you encounter while writing). Let the phases blur in practice while holding the distinctions conceptually.

2. **Infinite Capture without Expression**: the most common pathology of PKM systems. Someone builds an elaborate Second Brain over two years and never produces anything with it. CODE solves this by naming Expression as the terminal purpose — the test of whether the system is working. If you have not expressed anything in the past month, something in CODE is blocked.

3. **Distilling instead of Expressing**: some people distil so exhaustively that they never express. They spend hours summarizing notes they could have used directly in a draft. Distillation is meant to make expression faster, not to replace it. If you find yourself perpetually refining notes, set an expression deadline.
